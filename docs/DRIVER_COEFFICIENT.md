# 驱动系数机制说明（Driver Coefficient）

驱动系数是"行业指标 → 公司财务"的**传导放大器**：
**系数 = 行业指标变动 1%，公司某个财务指标随之变动百分之几。**

## 一、数据模型（financial_driver 表）

每条记录 = 一个"指标 → 公司财务"映射：

| 字段 | 含义 | 示例 |
|------|------|------|
| driver_name | 驱动名 | DRAM 合约价 / AI 芯片出货量 |
| impact_metric | 作用的财务指标 | revenue / gross_margin / eps / fcf |
| impact_direction | 方向 | positive（利好）/ negative（利空） |
| impact_coefficient | **系数（弹性）** | 1.2 / 0.9 / 0.25 |
| elasticity | 保守弹性（= 系数 × 0.8） | 0.96 / 0.72 / 0.2 |
| base_value | 建模锚点基准值 | 100（DRAM 2024 年水平） |
| confidence | 置信度 | 0.8 |

当前 9 条驱动（2026-08-27，均为分析师经验值）：

| 公司 | 驱动 | 作用 | 方向 | 系数 |
|------|------|------|------|------|
| NVDA | AI 芯片出货量 | revenue | + | 0.9 |
| NVDA | HBM 涨价传导 | gross_margin | + | 0.25 |
| AMD | AI 芯片出货量 | revenue | + | 0.6 |
| MRVL | AI 芯片出货量 | revenue | + | 0.7 |
| MU | DRAM 合约价 | revenue | + | 1.2 |
| MU | HBM 需求 | eps | + | 1.0 |
| MSFT | 云资本开支 | revenue | + | 0.5 |
| ORCL | 云资本开支 | revenue | + | 0.45 |
| GOOGL | 云资本开支 | revenue | + | 0.35 |

## 二、计算方式（Factor-First 引擎）

```
指标涨幅 = (新值 - base_value) / base_value
财务影响 = 指标涨幅 × impact_coefficient
```

⚠️ **口径注意**：引擎对比的是"相对 base_value（建模锚点）的累计变化"，
不是"相对指标当前值的边际变化"。base_value 通常取历史基期水平。

## 三、实战场景演示

### 场景 1：云资本开支上调 30%（420 → 546，相对基准 230 = +137.4%）

| 公司 | 系数 | 营收影响 | 排名 |
|------|------|---------|------|
| MSFT | 0.5 | +68.7% | 🥇 |
| ORCL | 0.45 | +61.8% | 🥈 |
| GOOGL | 0.35 | +48.1% | 🥉 |

业务逻辑：Azure 对 capex 弹性最高（资本开支最直接转化云收入）；
GOOGL 云业务占比小（~12%）最钝。

### 场景 2：DRAM 跌破基准 -20%（100 → 80）

| 公司 | 角色 | 驱动 | 影响 |
|------|------|------|------|
| MU | DRAM 卖家（收入端） | 合约价 → 营收 | **-24.0%** |
| MU | DRAM 卖家 | HBM 需求 → EPS | **-20.0%** |
| NVDA | HBM 买家（成本端） | 涨价传导 → 毛利率 | **-5.0%** |

**核心区别：收入端 vs 成本端**
- **收入端**（MU）：DRAM 即产品，价格直接乘系数（1.2，弹性 >1）→ 伤筋动骨
- **成本端**（NVDA）：HBM 仅是原材料之一，系数 0.25 且只影响毛利率 → 隔靴搔痒

## 四、系数怎么定（3 种方法）

| 方法 | 说明 | 现状 |
|------|------|------|
| ① 经验法 | 分析师对业务的理解拍板 | ✅ 当前在用 |
| ② 财务结构法 | 系数 ≈ 业务营收占比 × 价格传导率 | 可作交叉验证 |
| ③ 统计回归法 | SEC 营收 YoY ~ 行业指标 YoY 线性回归 | ⚠️ 实验失败，留作诊断 |

### 回归法为何失败（2026-08-27 实测）

`financial_model/calibrate.py` 用 SEC 年度营收与行业指标做回归，9 个驱动
**全部被安全阀拒绝**：
- 高成长股（NVDA 营收增速 50~200%）与全行业产出增速（5~10%）非线性
  ——份额扩张主导，而非行业总量
- 年度样本仅 4~5 个点，统计强度不足

安全阀规则（不达标拒绝写入，保留经验值）：
1. 系数方向与 impact_direction 矛盾 → 拒
2. 系数超出合理范围（0.05 ~ 3.0）→ 拒
3. R² < 0.5 → 拒

**结论**：当前数据粒度下统计回归不可靠，经验值 + 财务结构推导最稳；
校准器保留为诊断工具，待季度数据积累后重跑，R² 达标才自动启用。

## 五、系数如何被使用

| 功能 | 用途 |
|------|------|
| Factor-First 弹性排名 | "DRAM 涨价 20% 谁最受益" → 各公司影响排序 |
| 情景引擎（Bull/Base/Bear） | 正/负驱动数决定偏离幅度（每净正向驱动 +2% 弹性） |
| 回测（backtest.py） | 指标实际涨幅 × 系数预测方向，验证系数有效性（实测命中率 71.4%） |
